STEP 1

Ingest documents

Source quality matters. Real RAG systems parse documents, clean text, and preserve useful metadata.

Remember: Missing, stale, or poorly parsed source content makes reliable answers harder.
STEP 2

Chunk documents

Chunking splits long documents into smaller passages that can be retrieved independently. Overlap may preserve context across boundaries.

Experiment with chunk size and overlap. Small chunks can improve precision; larger chunks can preserve more context.
STEP 3

Embeddings and vectors

An embedding model maps text to a numeric vector. Similar meanings may produce nearby vectors. This demo uses illustrative text features rather than a real embedding model.

Production embedding vectors often have hundreds or thousands of dimensions. Individual dimensions generally do not have simple human-readable meanings.
STEP 4

Retrieve candidate chunks

Keyword search is useful for exact terms and identifiers. Vector search can find related meanings. Hybrid retrieval combines both signals.

STEP 5

Rerank the candidates

A real cross-encoder scores the query and each candidate together. It can improve relevance but is usually slower than first-stage retrieval.

Retrieval creates a shortlist; reranking carefully sorts that shortlist. This simulator approximates the process using text features.
STEP 6

Build context and generate an answer

The highest-ranked chunks become context for a language model. A production prompt should require grounded answers and citations.
